Step 1

Monthly users

Two numbers that multiply your bill

Active users means people who actually use the AI feature in a month, not everyone with a login. Requests per user per day is how often one of them presses the button. Two questions a day is light use; a tool someone works in all day is 20–50. Double either number and the cost doubles.

For this field, use people who actually trigger AI requests in a typical month. With the same behaviour per user, more users increase the total bill but do not change cost per user.

Step 2

Usage per user

You pay twice for every request

Billing is per token, roughly ¾ of a word, and you pay once for what you send and again for what comes back. Answers usually cost 4–10× more per token than prompts, so a chatty model can be expensive even with a small prompt. One page of text is about 500 tokens. A document or long system prompt attached to every request counts every single time.

Expected = realistic average. Max expected = high but plausible. Requests, prompt size and reply size multiply each other, so change one assumption at a time when testing.

What counts as a token?

Tokens are pieces of text. As a rough English-text guide, 1 token is about 4 characters. Input includes instructions, documents and conversation history; output is the model’s answer, including any billed reasoning tokens.

Measure a real prompt

Characters ÷ 4. A rough guide, not a tokenizer.

Step 3

Model

Pick the cheapest one that still gets it right

Bigger models reason better and cost more, sometimes dramatically more for the same job. The useful question is not which model is “best”; it is which is the cheapest model that still gets your task right. Start lower and move up only when quality actually fails your own tests.

Decision order

Three cost levers to test first.

There is no honest universal percentage split: the weight depends on your model and workload. These are the levers with the clearest effect.

1 · Model

Pass the quality test first

Same workload, different unit price.

How to find out: run the same 10–20 real tasks on a few models and compare quality, latency and cost.

2 · Request frequency

Count what one user action really triggers

Within the same model and token sizes, 2× as many API calls means about 2× the API cost.

How to find out: log actual API calls per user action, especially for agents, retries and tool loops.

3 · Prompt + reply size

Measure payload, history and output

Within the same model, doubling both input and output tokens roughly doubles token cost.

How to find out: inspect real usage tokens and watch repeated history, documents and long reasoning/output.

What no rate limit can cost you

Use it well

Who it is for

Founders, product owners, indie devs, agencies and technical PMs planning or pricing an AI feature.

Best way to use it

Start broad. Then keep everything fixed and change one thing at a time. Compare a few models and scenarios.

What it is not

Precise production billing. If you already have real usage telemetry, use that instead.

Simple planning rule: use Expected for your normal forecast and pricing maths. Use Max expected as the affordability check: the product should still be safe if that month happens. If Max expected would hurt, add limits, change the model, reduce usage, or change pricing before launch.

Plain English

What these words mean.

TokenA chunk of text, roughly ¾ of an English word. 1,000 tokens is roughly 750 words, but language and content change the ratio.

Input / user promptEverything you send: the question, system prompt, attached text/documents and relevant chat history.

Output / AI replyWhat the model writes back. Reasoning models may also report billable reasoning/output tokens depending on provider.

Cached inputRepeated context the provider can serve at a lower rate when its cache rules are actually met.

Context windowThe maximum the model can hold at once. It is a limit, not the amount you automatically pay for.

Batch / Flex / FastAlternative processing modes some providers offer. This estimator uses its saved standard-rate dataset unless explicitly stated otherwise.

Rate limitA cap on how often a user or client can call the API. One of the cheapest protections against runaway usage.

Where the prices come from

Every model links to the provider's own pricing page and carries the date its price was checked. Nothing is fetched while you use the tool — the prices are read into the estimator, so a provider redesigning a page cannot quietly change your numbers. Prices checked . Exchange rates: .

It is a guide, not a quote

Treat every figure as a rough order of magnitude. It is here to help you decide whether something is worth building, not to tell you what you will be invoiced. Before you commit money, check the provider's own pricing page — and no warranty of any kind is given on these numbers.

Left out on purpose: VAT and other taxes, volume discounts, unverified processing-mode discounts, image/audio/video generation pricing, and the retries and overheads of your own code.

Your numbers stay with you

No account, no server, no cookie, no analytics. Everything runs in your browser, and the share link carries your settings inside the URL itself. Close the tab and nothing is stored by this estimator. For a PDF, print the page (Ctrl/Cmd + P).
